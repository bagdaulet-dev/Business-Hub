# ТЗ: единый AI-поиск и явные фильтры

Дата: 2026-11-15. Заказчик: aibarC. Исполнитель приложения: bagdaulet-dev.
Статус: согласованное направление, НЕ описание уже реализованной функциональности.

## Цель и границы

Один сценарий для коллекционных карточек и техники: пользователь описывает товар, Kimi разбирает запрос, серверный код сопоставляет сохранённые объявления и сравнивает цены. В демо нет живого поиска eBay, мониторинга и риск-скоринга. Vercel, доступы и автодеплой сейчас не являются задачами или условиями готовности. Проверяем локально.

## Интерфейс

- Оставить одно широкое поле (лучше textarea с разумной высотой) «What are you looking for?». Подсказка: «Describe a product and your budget, e.g. Sony WH-1000XM5 under $250».
- Одна основная кнопка «Search». Каждый явный запуск поиска использует AI. Удалить отдельную кнопку «Search Pokémon with AI» и двойной режим поиска.
- «Автоматически через AI» означает при Search/отправке формы, НЕ на каждую букву, загрузку страницы или выбор примера. Не добавлять лишних запросов к модели.
- Кнопка «Filters» раскрывает/сворачивает блок: Model year, Max price (USD) и Item location (несколько стран). По умолчанию поля пусты. Краткая подпись: «Values entered here override your search text».
- Сворачивание панели сохраняет значения. При активных значениях возле Filters показывать число фильтров и/или компактные теги, чтобы скрытые ограничения были заметны.
- У каждого поля есть очистка; общий Clear search очищает текст, поля и результат. Очистка поля означает возврат к значению, распознанному из текста при следующем поиске; НЕ принудительное снятие текстового условия.
- Примеры сгруппировать «Collectibles» и «Electronics». Они подставляют полноценный запрос, не запускают API. При выборе нового примера сбрасывать старые ручные фильтры, чтобы бюджет/год другого товара не сохранялись незаметно.
- Не называть Sony/Canon синтетическими после подключения реальных данных; до этого не выдавать старые sampleProducts за реальные объявления. Источник маркировать для каждого набора.
- Во время запроса показать понятную загрузку, предотвратить дубли. При ошибке AI не переключаться молча на поиск по словам. Предложить повторить.

## Главный принцип: ручные фильтры имеют приоритет

Порядок обработки строго такой:
1. Проверить входные данные и отдельно разобрать текст Kimi.
2. Провалидировать результат модели.
3. На СЕРВЕРЕ наложить только явно переданные ручные фильтры.
4. Применить полученный effectiveRule к кандидатам и вычислить сравнение.
5. Вернуть интерфейсу итоговые условия и происхождение каждого переопределения.

Не приклеивать бюджет к текстовому промпту, надеясь, что модель разрешит конфликт. Это сейчас делает app.mjs; заменить структурированной передачей. Не фильтровать старый результат постфактум в браузере: если AI отрезал товары по меньшему бюджету, их уже нельзя вернуть таким способом.

Семантика: отсутствующий ключ = использовать AI; явно введённое валидное значение = заменить AI. UI не отправляет пустую строку или null вместо отсутствующего ключа. Ноль — валидный бюджет, не признак отсутствия. Отрицательное число, NaN, бесконечность, дробный год, некорректный формат и переполнение отклоняются до запроса к провайдеру. USD переводить в целые центы без потери точности.

Пример предлагаемого контракта (пока НЕ поддержан текущим endpoint):
```json
{
  "text": "Sony WH-1000XM5 under $200",
  "overrides": {"max_price_cents": 30000, "model_year": 2022}
}
```
Итог: бюджет $300, год 2022. Текстовое ограничение $200 не участвует в отборе. Показать «Max price: $300 · Set in filters», а не одновременно $200 и $300.

Год трактовать как год модели, а не дату изготовления/публикации лота. Не выводить его из даты сбора данных. Если справочник года не подтверждён, сохранять null; объявление с неизвестным годом не должно проходить строгий фильтр года. Годы Sony 2022 и Canon 2023 подтверждены отдельно источниками производителей в electronics-model-metadata.json; не переносить их на другие модели.

## Страны и место нахождения — для всех категорий

- В Filters добавить «Item location» с чекбоксами/поиском стран и несколькими выбранными тегами. Примеры: United States, Japan, South Korea. В API использовать ISO alpha-2: US, JP, KR; отображать человеческие названия.
- Источник — исключительно Item location / Located in объявления. Не путать со страной производства, регистрации продавца или доступной доставки. Город показывать в карточке, отдельный городской фильтр пока не нужен.
- Если страна не задана ни в тексте, ни вручную, показывать все страны, включая объявления с неизвестным местоположением (Location unknown).
- Несколько выбранных стран = OR: US или JP. С годом, моделью и бюджетом — AND.
- Страны, явно выбранные в Filters, полностью заменяют распознанные AI страны, а не объединяются с ними. В тексте Japan, вручную US + KR → только US + KR.
- Предлагаемый API: overrides.item_location_countries: ["US", "JP"]. Отсутствующий ключ = использовать AI. Пустой список [] = явно «All countries», отменяя географическое ограничение текста. Для UI различать начальное «From your search / All if unspecified» и ручное «All countries»; последнее реализовать простым действием «All countries» в меню. Clear filters возвращает автоматическое состояние. Это исключение к правилу пустых скалярных полей выше.
- Неизвестная страна не проходит непустой фильтр стран. Проверять массив, допустимые ISO-коды, удалять дубли; не принимать случайные строки/объекты.
- AI должен различать «located in Japan» и «ship to Kazakhstan». Второе не означает товар в Казахстане. Доставку по сохранённым данным пока не подтверждаем; такие запросы не превращать молча в фильтр местоположения.
- Фильтр стран применяется и к выдаче, и к допустимым аналогам. В подписи медианы указывать географический охват. При недостатке аналогов после фильтра — честное отсутствие оценки. Бюджет по-прежнему не ограничивает аналоги.
- Разница цен отдельных объявлений из разных стран НЕ доказывает, что одна страна дешевле: отличаются даты, гарантия, доставка и пошлины. Не вычислять «среднюю цену страны» по одному лоту.
- В data/demo/*source-observations.json сохраняются item_location_country_code, item_location_text и evidence. Null не заменять предположением по домену ebay.com.
- Использовать реальные записи разных стран для демонстрации смены выдачи. Country filter должен работать также для Charizard, даже если в имеющемся наборе подтверждена только US, а остальные местоположения неизвестны.

## Обработка разных товаров

Существующий AI-контракт имеет только поля карточек; текущий сервер читает только Charizard JSON. Поэтому переименование кнопки НЕ завершает задачу.

Предлагается валидируемый discriminated union по category: collectible_card / headphones / camera. Общие поля: нормализованная модель/идентификатор поддерживаемого товара, max_price_cents, model_year, дополнительные поддерживаемые условия. Специфические: номер/язык/PSA для карточек; состояние, цвет и комплектация для техники. Итоговый контракт согласовать с aibarC до параллельных правок engine/provider. Не позволять модели задавать цены, ссылки или новый каталог.

Неизвестная модель → понятный пустой результат/«This demo does not contain that product», без подстановки ближайшего другого товара. Неподдерживаемое условие не игнорировать молча.

Группы сравнения: одна модель, состояние, цвет, комплектация, валюта и тип предложения. Учитывать явно отличающиеся региональные/гарантийные версии и упаковку; candidate_only/eligible_for_median:false не включать в медиану. Такие объявления допустимы для списка исторических примеров и демонстрации фильтра стран с явными оговорками; сравнение цены по ним отсутствует. Canon body only не сравнивать с kit; Sony new не сравнивать с used/open box/refurbished. Не использовать аксессуары, неисправные товары, цены вариантов «от», старт аукциона, зачёркнутую цену и купоны с условиями как обычную фиксированную цену.

## Объяснение цены

Переименовать «Why this price?» в «Price comparison». Не обещать объяснять мотивы продавца.
- Your price: $350
- Median of 5 other comparable saved listings: $460
- Difference: $110 (23.9%) lower
- Item price only; shipping and tax not included.

Показать остальные объявления с ценами и ссылками и выделить текущий лот. Медиана считается БЕЗ текущего лота; бюджет ограничивает выдачу, НЕ набор аналогов. При менее чем трёх аналогах: «Not enough comparable listings», без процента и выдуманного ориентира. Это медиана сохранённой выборки, не доказанная рыночная цена или магазинная скидка. Текст объяснения формируется кодом, дополнительный LLM-вызов не нужен.

## Приёмка

1. Search для Charizard и каждого поддержанного товара вызывает серверный AI-разбор и выводит объявления правильной группы.
2. В тексте до $200, в фильтре $300 → используется $300, включая подходящие лоты выше $200. Обратный конфликт → используется меньший ручной бюджет.
3. В тексте другой год, в фильтре год выбранной модели → используется ручной год. Нужна реализация AI-поля года, а не только прежнего modelYear.
4. Пустые поля → сохраняются условия текста; очистка ручного поля возвращает текстовое условие. Бюджет 0 не превращается в «без ограничения».
5. Сворачивание/раскрытие не теряет фильтры; новый пример их сбрасывает. Итоговые условия видны рядом с выдачей.
6. Если AI не работает, понятная ошибка и повтор; ключ не попадает в клиент, DOM и логи.
7. Медиана не меняется при изменении только бюджета, если сравнивается тот же лот; текущий лот исключён из аналогов.
8. Нет результатов/мало аналогов/неизвестный год обрабатываются честно; неизвестную доставку не считать нулём.
9. Мобильный экран: весь запрос доступен для чтения/редактирования, Filters доступен с клавиатуры, не возникает горизонтального переполнения.
10. Видно, что это сохранённые объявления с неподтверждённой текущей доступностью. Отсутствует обещание live eBay или поддержки всех товаров мира.

11. Страны: пустой запрос по географии → все; US → только US; US+JP → объединение этих стран; неизвестные страны исключены при непустом фильтре. Ручной список заменяет AI, явное All countries снимает географию AI.
12. При смене запроса/фильтров во время ожидания старый ответ не выдавать за результат новых условий: отменить запрос или явно сохранить условия запущенного поиска и проигнорировать устаревший ответ.
13. Canon из разных регионов показывать как исторические предложения с указанной страной, без общей медианы, пока comparison eligibility не подтверждена. Out-of-stock запись не показывать как доступную покупку.
