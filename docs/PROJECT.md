## 1. Идея одной фразой

**Говоришь агенту, какую карточку ищешь и сколько готов заплатить, — он находит подходящие дешёвые объявления, объясняет сравнение цен и уведомляет о новых совпадениях.**

Решение пользователя: риск-скоринг исключён из MVP — без оценки подлинности, вероятности мошенничества и бейджей риска. Ценность подписки — экономия времени, точность совпадения и своевременные уведомления; преимущество «раньше всех» не заявляем без измерений. Ближайшее демо использует сохранённые наблюдения, живой мониторинг подключается позже.

Старт — карточки **Pokémon** (самый горячий сегмент), затем спортивные карточки, кроссовки, LEGO, винил, комиксы — внутри рынка США.

## 2. Проблема

- Коллекционер часами листает eBay, а выгодные лоты уходят за минуты.
- Названия лотов хаотичные — непонятно, это та же карточка/та же оценка PSA или нет, сколько она реально стоит.
- Сложно быстро найти более дешёвое предложение именно нужной версии карточки.
- Существующие инструменты либо просто сообщают «появился лот» (сохранённый поиск eBay), либо считают стоимость коллекции (Collectr, Card Ladder) — **наше целевое отличие — поиск подходящей цены и уведомления**; утверждения о возможностях конкурентов требуют проверки.

## 4. Решение (что делает агент)

1. **Понимает запрос.** Название, выпуск, номер, язык, оценка и бюджет превращаются в условия поиска.
2. **Находит совпадения.** В демо — сохранённый набор; после доступа — eBay Browse API и фоновые проверки.
3. **Сопоставляет одинаковые варианты.** Наборы, футляры, реплики и другие версии исключаются как неподходящий товар, без оценки мошенничества.
4. **Сравнивает цены.** Медиана остальных сопоставимых предложений, исключая оцениваемый лот. Бюджет фильтрует кандидатов, а не базу аналогов. При недостатке данных результат неизвестен.
5. **Объясняет разницу.** Показывает аналоги, размер выборки и основу расчёта: цена товара либо цена с доставкой на один адрес, без смешения этих основ. Дешевизна сама по себе не является признаком риска.
6. **Уведомляет.** Telegram и ссылка на объявление; тестовая отправка в демо обозначается явно. После живого источника — уведомления о новых совпадениях без дублей.

Цена объявления не равна цене продажи; исчезновение объявления не доказывает продажу. Для сохранённых наблюдений используем формулировку «ниже медианы этой выборки», а не доказанную скидку от рынка. Покупка происходит на eBay; не обещаем собственную проверку подлинности или безусловное покрытие всех рисков площадкой.

## 10. Продукт: экраны MVP

1. **Главная / «Скажи агенту, что ищешь».** Поле ввода + примеры-кнопки («Charizard PSA 10 до $500», «Pikachu Illustrator», «Umbreon VMAX Alt Art до $300»).
2. **Находки.** Карточки лотов: фото, цена, доставка, **разница с медианой аналогов (если вычислима)**, рейтинг продавца, «аукцион/купить сейчас», таймер для аукционов, кнопка «Открыть на eBay». Сортировка по выгоде.
3. **Детали лота.** Почему подходит: совпавшие характеристики, цены аналогов, основа расчёта и неизвестные сведения. Оценки риска нет.
4. **Мои охоты.** Список активных охот агента, частота проверки, последние находки, подключение Telegram.
5. **Тарифы.** Free / Pro / Hunter (без реальной оплаты в демо).
6. *(если успеем)* **Моя коллекция** — добавить карточки и видеть стоимость.

Без регистрации: охоты привязаны к анонимной сессии (cookie).

## 11. Техническая реализация

### Стек
- **Next.js (TypeScript, App Router)** — фронт + API-роуты, деплой на **Vercel**.
- **Postgres** (Neon или Supabase, бесплатный тариф) — у Vercel нет постоянного диска.
- **Claude API** — разбор правил и названий лотов (structured outputs → гарантированный JSON).
- **eBay Browse API** — поиск лотов.
- **Telegram Bot API** — уведомления (самое эффектное на сцене).
- **Планировщик** — внешний пинг эндпоинта `/api/cron/hunt` раз в 1–5 минут (cron-job.org / Upstash QStash / GitHub Actions). Встроенный Vercel Cron на бесплатном плане запускается только раз в день.

### Пайплайн
```
Охота (текст) → Claude: правило JSON
Планировщик → для каждой уникальной поисковой фразы: eBay search (дедупликация запросов)
  → новые лоты → Claude: нормализация названия (кэш по itemId)
  → матчинг с правилом (карта, сет, номер, грейдер, оценка)
  → медиана остальных сопоставимых предложений (или недостаточно данных)
  → разница цен и объяснение, сортировка по условиям пользователя
  → если проходит правило: сохранить находку + уведомить
```

### eBay API — детали
- **Аккаунт:** developer.ebay.com → Application Keys → keyset **Production**.
- **Обязательное условие для Production:** endpoint уведомлений об удалении аккаунтов (Marketplace Account Deletion).
  - URL: `https://<домен>/api/ebay/account-deletion`, verification token 32–80 символов (`[A-Za-z0-9_-]`).
  - GET `?challenge_code=...` → ответ `{"challengeResponse": sha256_hex(challenge_code + verification_token + endpoint_url)}`, 200, `application/json`.
  - POST (уведомления) → 200.
- **Токен приложения** (живёт 2 часа, обновлять автоматически):
  `POST https://api.ebay.com/identity/v1/oauth2/token`, Basic auth `client_id:client_secret`, body `grant_type=client_credentials&scope=https://api.ebay.com/oauth/api_scope`.
- **Поиск:** `GET https://api.ebay.com/buy/browse/v1/item_summary/search?q=...&category_ids=183454&filter=price:[100..500],priceCurrency:USD&limit=50`
  заголовки `Authorization: Bearer <token>`, `X-EBAY-C-MARKETPLACE-ID: EBAY_US`.
  `183454` — CCG Individual Cards (сверить через Taxonomy API `get_category_suggestions`).
- **Поля ответа:** `itemSummaries[]`: `itemId`, `title`, `price`, `shippingOptions`, `image`, `seller.feedbackPercentage`, `seller.feedbackScore`, `itemWebUrl`, `buyingOptions`, `itemEndDate`.
- **Лимит:** 5,000 вызовов/день по умолчанию → дедупликация одинаковых поисков + кэш.
- **Партнёрка (позже):** eBay Partner Network, заголовок `X-EBAY-C-ENDUSERCTX: affiliateCampaignId=...` → `itemAffiliateWebUrl`.

### Claude API
- Ключ `ANTHROPIC_API_KEY` — только на сервере.
- Модель по умолчанию — `claude-opus-5-5`; для массового разбора названий команда может выбрать `claude-haiku-5-5` (дешевле).
- Structured outputs: схема лота `{card_name, set_name, card_number, language, grader, grade, is_first_edition, is_lot_or_bundle, item_type, mismatch_reasons[]}`; схема правила `{query, card_name, set_name, grader, min_grade, max_grade, max_price, min_discount_pct, buying_options[]}`.
- Код писать по официальной документации SDK `@anthropic-ai/sdk`.

### Модель данных (Postgres)
- `sessions(id, created_at, telegram_chat_id)`
- `hunts(id, session_id, text, rule_json, plan, check_every_min, last_checked_at, active)`
- `listings(item_id PK, title, parsed_json, price, shipping, currency, seller_feedback_pct, seller_score, image_url, url, buying_option, end_date, first_seen_at, last_seen_at, gone_at)`
- `finds(id, hunt_id, item_id, reference_price, comparison_basis, comparable_item_ids[], discount_pct, notified_at)`
- `price_history(card_key, grade_key, price, observed_at, source)`

### Проверка соответствия и качества данных
- Исключать неподходящие варианты, наборы, аксессуары и явно обозначенные реплики из поиска оригинальной карточки.
- Не превращать цену, отзывы или страну продавца в fraud/risk score.
- Неизвестные поля сохранять как null; предупреждения о доставке, давности и нехватке аналогов описывают качество данных, а не безопасность покупки.
- Финальные типы принадлежат bagdaulet-dev; не добавлять risk_score, risk_level или risk_signals в контракт, БД, промпты и UI MVP.

## 12. Демо на питче (сценарий 60–90 секунд)

1. Показываем маркировку сохранённых данных и их ограничения по давности.
2. Вводим «Charizard ex 199/165 English PSA 9 до $450»; приложение реально разбирает условия и фильтрует набор после реализации обработки.
3. Открываем самый дешёвый подходящий результат и аналоги. Число совпадений определяется данными, не обязано равняться одному.
4. Если подключён Telegram, выполняем явно обозначенную тестовую отправку.
5. Меняем бюджет или карточку и показываем изменившийся/пустой результат.

Текущий набор: шесть исторических наблюдений разной давности, доставка для разных ZIP. Расчёт только по цене товара не выдавать за доступную сейчас экономию с доставкой. Для актуального снимка повторно проверить объявления на одну дату и адрес. Живой поиск и непрерывный мониторинг показывать только после проверки интеграции.

## 14. Ответы на вопросы жюри

- **Чем лучше бесплатного сохранённого поиска eBay?** Он говорит «появился лот». Мы проверяем совпадение нужной версии и бюджета, показываем сравнение с аналогами и уведомляем о подходящих предложениях.
- **Откуда рыночная цена?** В демо — медиана остальных сопоставимых сохранённых цен с указанной давностью; это не оценка всего рынка и не история подтверждённых продаж.
- **Как привлекаете клиентов дёшево?** Коллекционеры живут в сообществах (TikTok, YouTube, Reddit, Discord); контент «агент нашёл −30%» и «поделись находкой» — органический рост.
- **Почему вернутся?** Рынок меняется каждый день, агент приносит новые находки, коллекционеры покупают регулярно.
- **Агент покупает сам?** Нет. Пользователь переходит по ссылке на eBay и самостоятельно оформляет покупку.
- **Как дойти до $100M?** 555K платящих в США при ARPU $180 — около 2% онлайн-покупателей коллекционных вещей; расширение по категориям внутри рынка США $32.1B.
