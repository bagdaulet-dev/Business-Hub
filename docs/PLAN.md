# CollectWatch — план двух участников с AI-агентами

Согласовано пользователем: **aibarC — данные, AI и оценка; bagdaulet-dev — приложение, backend и развёртывание**.
Текущий путь к демо — сохранённый набор реальных объявлений; подтверждение developer-аккаунта eBay ожидается по сообщению aibarC. Живой поиск не блокирует разработку демо. Этот план заменяет прежние этапы BE/FE и оценки в часах. Дата исходного брифа — 15 ноября 2026, 12:00; актуальное время сдачи нужно подтвердить, не выводить из относительного «завтра».

Решение пользователя: **риск-скоринг исключён из MVP**. Фокус — дешёвые подходящие объявления, прозрачное сравнение и уведомления. Не добавлять fraud probability, оценку подлинности или бейджи риска. Проверки соответствия товара и полноты данных сохраняются.

Документация не означает реализацию. Все задачи ниже пока не подтверждены выполненными. Отмечать `[x]` только с указанием проверенного результата/коммита. Продуктовый бриф: [PROJECT.md](PROJECT.md); правила работы: [../AGENTS.md](../AGENTS.md).

Общие AGENTS.md/PLAN.md/PROJECT.md меняет один назначенный редактор за раз; после этой публикации координатор общих документов — bagdaulet-dev. aibarC передаёт изменения статуса и предложения в описании своей передачи/PR.

## 2. Ветки и передачи

- aibarC: `work/data-engine`; bagdaulet-dev: `work/app`. Создать от свежего main при начале реализации; один владелец ветки.
- Изменения разработки публиковать в свою ветку и оформлять PR в main. Интегратор — bagdaulet-dev: последовательно проверяет и объединяет изменения, выполняет финальный деплой.
- Общий контракт сначала попадает в main отдельным небольшим изменением. Затем обе рабочие ветки получают его; не поддерживать две копии типов.
- Опубликованные ветки обновлять обычным merge свежего origin/main, без переписывания истории. Не сливать чужую незавершённую ветку целиком для получения одного файла.
- Дополнительным субагентам выделять независимые файлы; при отдельных checkout использовать уникальные дочерние ветки. Не давать двум редакторам общую рабочую копию с пересекающимися изменениями.
- Передача: SHA/PR, изменённые файлы, способ вызова, выполненные проверки, ожидаемые результаты, ограничения и необходимые имена переменных (без значений).
- Изменения чужой зоны сначала передавать владельцу. При явном согласовании временной передачи зафиксировать файлы и завершение передачи; не редактировать параллельно.

## 5. Этап 2 — обработка и сервер параллельно

### aibarC: модуль обработки

- [ ] Реализовать `parseRule(text)` с валидацией AI-ответа, понятной ошибкой и ограниченными сетевыми ожиданиями. Не выдумывать условия пользователя.
- [ ] Реализовать нормализацию и `matchListings`: исключать несовместимые версии, наборы и неподходящие оценки.
- [ ] Реализовать детерминированный расчёт: исключать оцениваемый лот из его аналогов, сравнивать одинаковую основу стоимости.
- [ ] Не ограничивать базу аналогов бюджетом запроса: бюджет фильтрует кандидатов, иначе ориентир цены будет смещён.
- [ ] Согласовать минимум аналогов; при недостатке аналогов возвращать null с объяснением. При неизвестной доставке полная стоимость остаётся null; сравнение цены товара допускается только с явной основой item_price и подписью «без доставки и налогов». Не смешивать основы сравнения.
- [ ] Для снимка писать «ниже медианы этой выборки», показывать аналоги. Цена предложения не равна цене продажи; исчезнувший лот не считается проданным автоматически.
- [ ] Возвращать причины несовпадения и нехватки данных; не вычислять риск подделки, аномальность или безопасность покупки. LLM разбирает текст; арифметику и фильтры выполняет код.
- [ ] Проверить расчёты на контрольных случаях, включая неизвестную доставку, другой grade, отсутствие совпадений и сбой AI.

### bagdaulet-dev: серверный сценарий

- [ ] Реализовать HTTP endpoint, валидацию ввода и вызов согласованного интерфейса обработки через временный модуль.
- [ ] Подключить frontend к endpoint, передавать ошибки и предупреждения без потери смысла.
- [ ] Настроить серверные переменные: AI-ключ не отправляется браузеру, логи не содержат секретов.
- [ ] Проверить загрузку, повторные отправки и отображение всех вариантов ответа.

**Выход:** модуль aibarC вызывается без UI/HTTP/БД-зависимостей; приложение bagdaulet-dev готово принять его через контракт.
